# Lessons Learned

1. Data profiling and quality checks are important before performing business analysis.
2. Correctly identifying data types and date formats is necessary for reliable time-based analysis.
3. Independent calculations help verify dashboard KPIs and improve confidence in analytical results.
4. SQL, Python, and Power BI can support different stages of the same business analytics workflow.
5. Visualizations should be checked against their underlying calculations rather than judged by appearance alone.
6. Risk-review indicators must be interpreted carefully and should not be treated as confirmed fraud.
7. Running a Python notebook from a fresh kernel helps identify dependencies on previous execution state.
8. Slicer and chart-interaction testing is necessary to check whether an interactive dashboard behaves as intended.
9. Clear documentation of assumptions, limitations, corrections, and validation results makes a project easier to review.
10. Organizing files and evidence in GitHub makes the project more accessible to reviewers and potential employers.
